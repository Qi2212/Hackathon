ABOUT CAMPUSGROVE

CampusGrove 是什么？

CampusGrove（校园 GPU 算力互助网络）希望解决校园里两件同时发生的事：一边是同学做实验排不到卡，另一边是实验室工作站和个人 GPU 在某些时段闲置。我们把这些资源放进一个可发现、可申请、有授权与记录的协作网络。

借用者用一份实验需求找到合适资源；贡献者保留个人 GPU 的授权权利；实验室和协作组按成员关系开放公共卡。项目把资源归属、卡主计划、条件排队预测、申请审批和贡献收支放在一起，让“谁的卡、什么时候能借、需要谁同意”更容易理解。

建议首次体验：选择林同学 → 算力大厅点开一张 3D GPU → 提交实验并分析 → 生成方案与预估 → 核对后申请 → 我的任务查看结果。下方可以按借用者、贡献者、小组成员分别阅读。

01 · 登录与认识资源范围

  1. 登录页选择测试用户，无需密码。点击左下角当前账号或右上角头像，可以切换身份。
  2. 林同学适合体验借卡；周同学适合体验个人 GPU 的卡主审批；独立贡献者可体验大厅资源；不同实验室账号可比较资源可见范围。
  3. 大厅公共卡全校可见；实验室公共卡仅本实验室可见；协作组公共卡仅组内可见；个人私有卡可以被发现，但借用需要卡主授权。
  4. “我的画像”描述当前个人的实验习惯、资源和交互样本。切换账号后，任务、审批与画像也会切换。

02 · 看懂大厅与 GPU 详情

  1. 先用型号、资源范围、空闲状态筛选，或搜索工作站和卡主。
  2. 每个 3D 小电脑代表一张物理 GPU，固定四个槽位一排；蓝色为空闲，青色为任务占用，紫色为卡主自用，灰色为离线。窄屏可左右滚动。
  3. 点击具体 GPU 查看单卡任务；点击工作站详情查看整机。详情分为“计划与可用性”“当前任务”“规格与收益”。
  4. 卡主进度曲线展示预制项目计划，24 / 48 / 72 小时色带展示条件共享窗口；公共卡展示容量曲线。它们是模拟计划，不能当作实际 GPU 利用率。
  5. 点击“按这个规格提交实验”带入型号与显存。最终分配节点仍由申请策略与可用容量决定。

03 · 一张表，完成实验分析

  1. 填写实验名称与目标，选择训练、微调、推理、交互、数据处理或仿真。目标描述影响语义提示，实验类型决定执行拆解。
  2. 选择型号、GPU 数量、单卡显存与时长。GPU 数量需要在同一节点满足；单次申请支持 15 / 30 / 60 分钟。
  3. 预算按“卡数 × 小时 × 节点卡时价”估算。设置截止时间，可检查预计结束是否超时。
  4. 设置分析范围、灵活度、是否允许中断、是否支持检查点，再点击“分析当前实验”。本页使用已就绪的本地模拟 API，无需填写 key，不会调用外部大模型。
  5. 阅读结论、候选节点、积分、条件开始 / 结束时间与风险原因。分析不会占卡，也不会自动替你改写填写的规格。

04 · 生成方案与正式申请

  1. 分析中的推荐策略供你参考。在“你更在意什么”里主动选择经济、算力、稳定或均衡。
  2. 点击“生成方案与预估”，比较四种方案并查看右侧队列顺位、等待原因和预计开始 / 结束时间。
  3. 核对最下方确认摘要，再点击“确认摘要并申请”。提交会复用这份方案；修改输入后必须重新生成。
  4. 公共资源可直接进入分配流程。个人私有资源先产生审批，请切换到对应卡主，在“共享审批”同意，再切回申请人确认提交。
  5. 在“我的任务”查看运行、分配与租约状态。实验结束主动释放；检查点和恢复操作是演示流程，需要手动触发。

05 · 相同页面，为什么分析结果不同？

型号、数量、显存与时长

显存设到约 40 GB 时，24 GB 的 RTX 4090 / 3090 无法满足；数量超过任何一个候选节点可提供的卡数，也会显示没有窗口。时长增加会增加积分和预计结束时间，系统不会凭空认定多卡一定更快。

目标和任务类型

训练给出训练 / 验证 / 检查点步骤；微调给出模型适配与权重导出步骤；推理给出批处理与结果汇总步骤。描述中出现 LoRA、多模态或大模型，会出现相应检查提示；结构化规格仍以表单为准。

预算、截止期与稳定性

预算太低会提示预算不足；截止期早于条件结束时间会提示超时。希望尽快开始会推荐更快开始的策略；成本优先推荐经济策略；不允许中断优先推荐稳定策略。无检查点会提示进度损失风险。

分析与方案的关系

分析基于当前租约推测未来窗口；正式方案主要检查此刻的可分配资源，因此两者可能不同。分析的时间未扣除全部前序排队竞争，也未计入私有卡审批。正式申请以生成方案与最终确认时的校验为准。

06 · 贡献资源、收益与事件记录

  1. 在“贡献资源”填写工作站 CPU、内存、存储、GPU 型号 / 显存 / 数量，或按页面模板导入 JSON。
  2. 登记后是草稿。核对后显式发布，才进入演示调度账本；发布的个人卡仍保留卡主审批。
  3. 没有活动租约时可以撤回；登记、发布、撤回记录按账号保存，重启后仍可查看。
  4. “收支”展示近 30 日合成样本，展开可看公共 / 私有来源、贡献者与平台分配。现场新任务不会自动计入历史收支。
  5. “事件回放”用于解释分析、查看资源、审批等操作。请区分预制审批案例与现场申请：批复案例不会真的创建一笔现场任务。

07 · 五分钟演示脚本

  1. 用林同学进入大厅，对比公共资源和个人资源，点开 GPU 看卡主计划。
  2. 提交页填写 1 张 RTX 4090、约 20 GB 显存、30 分钟、预算 20；运行分析观察候选与估价。
  3. 将预算改为 0 再分析，观察费用风险；将显存改为约 80 GB 再分析，观察不兼容结论。
  4. 恢复可行规格，生成方案，核对确认后申请。私有卡按提示切换卡主审批。
  5. 查看我的任务和队列，释放资源；最后切到贡献者账号，演示登记 → 发布 → 安全撤回。

08 · 常见问题与演示边界

为什么没有数据或显示任务服务未连接？

在项目根目录执行 python run.py，并访问启动日志给出的 HTTP 地址；不要直接双击 index.html。默认由启动器同时拉起资源服务和任务服务。若提示端口占用，先检查原有服务。

是真实运行训练吗？需要 Excel 或 API key 吗？

这里是系统流程 Demo，资源和任务是模拟状态，不会调用真实 GPU 训练。数据由项目代码合成，不读 Excel。提交页模拟分析不需要真实 API key；真实大模型接入属于另一种可选配置。

预测会自动帮我占卡或派发吗？

不会。排队预测是假设租约按时结束的条件推演，不是预约；尚未实现完整的 Pending 自动派发和 TTL 自动释放。租约到期也不等于模型训练完成。

小组能创建吗？重启后数据如何变化？

目前可以查看预制小组及其权限范围；创建、邀请、成员管理尚未实现。核心模拟任务场景在重启后恢复；意愿分析、交互、审批案例和用户登记资源另以本地文件持久保存。

你在页面上看到的状态

排队中→已分配→运行中→已释放

排队还没有占卡；分配成功才开始计算租约。租约到期时间与任务完成时间不同。

私有卡还会多一步「卡主审批」。批准后，由申请人确认提交。

几件容易混淆的事

公共卡和私有卡有什么区别？

公共卡按当前策略申请；个人私有卡保留卡主授权。组内实验室公共卡与个人私有卡分别展示归属。

详情里的曲线，代表什么？

项目曲线来自预制演示计划；可共享时段按卡主声明和现有租约推算。它们不是实际 GPU 监控，也不保证资源一定可用。

贡献收益如何查看？

个人画像显示该账号的历史收支和拥有的 GPU；收支页可展开查看资源来源与平台分配。历史汇总不会随现场新任务自动结算。

这次 Demo，可以怎样体验

选择账号 → 查看卡主计划 → 预估方案 → 申请资源 → 在「我的任务」里查看状态。私有卡需切换到对应卡主审批，再切回申请人提交。

实验室与小组资源已按演示身份过滤；小组创建 / 邀请、自动派发和完整 TTL 自动释放尚未完成。画像预测为可解释统计基线，不是训练完成的模型；现场交互保存为 JSON / JSONL 文件。

演示控制与数据说明

默认数据为 12 个节点 / 34 张 GPU。全部数据由项目内代码合成，无需 Excel；执行 python -m tools.build_demo_seed 可重新生成。重启会恢复场景。测试密钥与模型 API key 不同。
