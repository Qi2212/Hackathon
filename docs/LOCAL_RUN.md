# CampusGrove 本地运行说明

适用于当前仓库的 Windows / PowerShell 演示。项目名称为 CampusGrove，底层服务和部分历史文档仍使用 Campus GPU Fabric / Aurora 名称。

配套讲稿：[DEMO_SCRIPT.md](DEMO_SCRIPT.md)。建议先完成本文的启动与演前检查，再照讲稿操作。

## 1. 运行需要什么

| 项目 | 要求 |
| --- | --- |
| 系统与终端 | Windows，PowerShell |
| Python | Python 3.11 或以上；用 `python --version` 检查 |
| 浏览器 | Edge 或 Chrome |
| 网络 | 首次安装 Python 依赖需要能访问包源；安装完成后的默认演示无需外部模型服务 |
| GPU | 演示电脑不需要真实 GPU，也不需要 CUDA |
| 其他 | 不需要 Excel、数据库、Redis，也不需要 Node.js 或前端构建 |

这是系统流程 Demo。后端接口会实际改变本地模拟资源、任务和审批状态；不会在真实 GPU 上启动训练。提交页的“分析当前实验”使用本地模拟 API，不需要真实 API key。

## 2. 首次安装

在 PowerShell 中执行：

```powershell
Set-Location 'D:\spring_boot_content\Hackathon'
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

后续命令直接使用虚拟环境里的 Python，无需激活环境，也不用修改 PowerShell 的脚本执行策略。

项目已附带 `app/data/demo_seed.json`。仅在文件缺失，或你修改了合成数据代码后，才需要重新生成：

```powershell
.\.venv\Scripts\python.exe -m tools.build_demo_seed
```

该命令从项目代码生成模拟场景，不读取 Excel。修改数据或重新生成后，需要重启服务。生成器使用固定的演示时间锚点，重新生成不会自动把场景日期改为今天。

## 3. 推荐启动方式：一个终端启动两个服务

在项目根目录执行下面整段命令。这里显式选择本地规则模式，避免已有的模型配置影响演示。

```powershell
Set-Location 'D:\spring_boot_content\Hackathon'
$env:FABRIC_DEMO = '1'
$env:LLM_PROVIDER = 'none'
$env:RELOAD = '0'
$env:FABRIC_EXT_AUTOSTART = '1'
$env:PORT = '8080'
$env:EXT_PORT = '8090'
$env:FABRIC_BASE_URL = 'http://127.0.0.1:8080'
$env:EXT_BASE_URL = 'http://127.0.0.1:8090'
.\.venv\Scripts\python.exe run.py
```

保持终端开启，在浏览器打开：

**http://localhost:8080**

不要双击 `app/static/index.html`。页面依赖后端接口，需要从 HTTP 地址访问。

`run.py` 默认启动资源服务和任务扩展服务，不要再额外运行一次 `run_ext.py`，否则可能发生 8090 端口冲突。

| 地址 | 用途 |
| --- | --- |
| http://localhost:8080 | 当前产品演示界面，现场只需要打开这个 |
| http://localhost:8080/docs | 资源服务接口文档，排查时使用 |
| http://localhost:8090/docs | 任务扩展服务接口文档 |
| http://localhost:8090/ui/ | 独立的接口工作台，作为调试补充 |

### 确认两个服务正常

另开一个 PowerShell 窗口执行：

```powershell
Invoke-RestMethod 'http://localhost:8080/healthz'
Invoke-RestMethod 'http://localhost:8090/ext/v1/healthz'
```

第二个结果应显示上游资源服务可达。页面左下角应显示资源已连接，提交页应显示任务服务已连接。

## 4. 需要干净场景时怎么启动

主流程建议使用一次全新的演示目录，避免之前登记的 GPU、分析记录或审批案例影响展示。

在第 3 节启动命令中，运行 `run.py` 前额外执行：

```powershell
$env:CAMPUS_DEMO_DATA_DIR = Join-Path (Get-Location).Path ('.app\demo-session-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
```

这会新建一个会话数据目录，不删除原有记录。每次使用新的目录名，都从内置场景和预制案例开始。

若想在下次启动时继续这一轮的持久化记录，给 `CAMPUS_DEMO_DATA_DIR` 设置同一个目录路径即可。若想恢复项目默认存储位置，在启动前执行：

```powershell
Remove-Item Env:CAMPUS_DEMO_DATA_DIR -ErrorAction SilentlyContinue
```

这条命令只移除当前终端的环境变量，不删除任何文件。

### 重启后哪些内容会保留

| 内容 | 行为 |
| --- | --- |
| 现场创建的核心任务、租约、任务草稿和现场审批 | 主要存于进程内存；完整重启两个服务后重新开始 |
| 内置节点、运行任务、等待任务 | 恢复合成场景 |
| 意愿分析、交互审计、预制审批案例的处理结果 | 存于本地文件，使用同一目录时保留 |
| 用户登记、发布和撤回的模拟资源 | 存于本地文件，已发布资源会重新加载 |
| 当前浏览器所选账号 | 浏览器本地保存；可从左下角切换，或在使用指南退出体验 |

所以，“重启”不等于“清空所有演示记录”。需要可重复排练时，优先使用新的会话目录。

## 5. 测试账号与推荐用途

测试账号无需密码，是 Demo 身份切换，不是生产认证。

| 账号 | 推荐用途 |
| --- | --- |
| 林同学 | 主讲账号：发现算力、提交实验、查看个人画像与任务 |
| 周同学 | 私有卡审批：拥有 `bio-ws-01` 的 RTX 3090 |
| 尹同学 | 独立用户与个人 GPU 贡献体验 |
| 蔡老师 | 查看实验室与协作组视角 |

更多测试成员可在登录页的其他账号选项中选择。点击左下角账号可切换身份。切换后重新核对表单和当前页面，不要假定上一身份的申请草稿仍然有效。

## 6. 演前检查与推荐参数

建议提前 10 分钟启动，并按顺序检查：

1. 用林同学登录，打开算力广场，确认资源卡和图表有数据。
2. 新会话默认全局场景为 12 个节点、34 张 GPU；林同学可见的节点数会受实验室和小组权限过滤，不一定显示全部 12 台。
3. 点开个人 GPU，检查计划曲线、共享窗口和规格页。
4. 提交页使用下面的主流程参数，点击“分析当前实验”，应出现分析结论。
5. 点击“生成方案与预估”，检查能生成方案。正式演示前不要反复申请占满资源；已申请的测试任务请主动释放。
6. 验证浏览器缩放为 100%，修改前端后按 Ctrl + F5 刷新；提前展开需要使用的侧栏分组。

推荐的公共资源主流程：

| 字段 | 填写内容 |
| --- | --- |
| 实验名称 | 校园多模态检索演示 |
| 研究目标 | 完成多模态检索模型的对比实验，保存最佳检查点并输出评测报告。 |
| 实验类型 | 模型训练 |
| GPU 型号 / 数量 | H100 / 1 张 |
| 单卡最低显存 | 约 20 GB |
| 使用时长 | 30 分钟 |
| 预算 | 20 积分 |
| 分析资源范围 | 公共大厅 |
| 时间灵活度 | 可错峰排队 |
| 中断 / 检查点 | 均勾选 |
| 截止时间 | 留空，避免演示时间与电脑日期混淆 |
| 正式申请策略 | 综合均衡 |

新场景下 H100 来自 `central-01` 公共节点，参考价 4.8 积分 / 卡时，1 张运行 30 分钟的使用估价约 2.4 积分。具体可申请状态以现场方案为准。

### 快速验证“输入不同，分析不同”

- 把预算从 20 改为 0，再分析：出现预算不足。
- 把型号改为 RTX 4090，最低显存改为约 80 GB，再分析：出现无兼容资源窗口。
- 把类型改为批量推理，再分析：执行步骤变为模型载入、分批推理、结果汇总等。
- 取消允许中断，再分析：推荐策略偏向稳定；不支持检查点则出现进度损失提醒。

演完对比后，恢复上表参数，重新分析、生成方案，再确认申请。修改字段会使旧方案失效，这是预期行为。

## 7. 停止、再次启动与更换端口

在运行 `run.py` 的终端按 Ctrl + C，等待程序退出。启动器会尝试同时停止它拉起的任务扩展服务。下次继续运行第 3 节命令即可。

如果端口已被其他程序占用，可使用一组新端口；四个地址配置需要保持一致：

```powershell
$env:PORT = '18080'
$env:EXT_PORT = '18090'
$env:FABRIC_BASE_URL = 'http://127.0.0.1:18080'
$env:EXT_BASE_URL = 'http://127.0.0.1:18090'
.\.venv\Scripts\python.exe run.py
```

此时访问 http://localhost:18080。不要直接结束不明进程。

## 8. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| `python` 不是命令 | 检查 Python 是否安装并加入 PATH；可先试 `py -3 --version`，创建环境时相应使用 `py -3 -m venv .venv` |
| 找不到 fastapi / dotenv / multipart | 确认使用 `.venv\Scripts\python.exe`，再用该解释器安装 requirements.txt |
| 页面无数据 | 从 localhost 的 HTTP 地址进入；检查终端报错、8080 健康接口，以及 FABRIC_DEMO 是否为 1 |
| 能看卡，不能生成方案 | 检查 8090 健康接口和上游可达性；核对 FABRIC_BASE_URL / EXT_BASE_URL，避免启动两个扩展进程 |
| 改完代码仍显示旧页面 | 浏览器按 Ctrl + F5；后端修改需要停止后重启 |
| 切换账号后看不到某些工作站 | 实验室 / 小组权限过滤的预期结果；公共大厅与可发现的个人卡仍按规则展示 |
| 确认按钮不可用 | 检查是否重新生成当前输入的方案；核对预算、型号、显存、卡数、截止期与空闲容量 |
| 私有卡申请后没运行 | 切换到界面提示的卡主处理现场审批，再切回申请人确认提交 |
| 等了一会儿，Pending 还没运行 | 当前未实现完整自动派发；队列预测不构成占卡承诺，不要靠等待完成主流程 |
| 没有真实 API key | 当前提交页模拟分析无需 key；启动时设 LLM_PROVIDER=none 即可完成演示 |
| 日期不是今天 | 场景使用固定逻辑时间，页面右上角可见演示时钟；填写截止期时必须留意这一点 |

## 9. 数据与功能口径

数据由 `app/synthetic.py` 合成，资源种子在 `app/data/demo_seed.json`，个人项目计划样例在 `app/data/experience_plans.json`。默认持久化记录位于 `.app/` 下；配置了会话目录时，以指定目录为准。

演示时可准确表达为：“接口驱动的本地算力协作流程，使用合成资源和任务样本。”

不要把以下内容讲成已经完成：真实 GPU 训练与硬件接入、实际训练进度监控、生产认证、自助小组创建和邀请、完整 Pending 自动派发与 TTL 自动释放、现场任务对近 30 日历史收益的自动结算。

队列时间是条件推演，卡主曲线是预制计划，画像是演示统计基线；模拟分析不会调用外部大模型。
