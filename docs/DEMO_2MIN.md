# CampusGrove 两分钟演示讲稿

两分钟只展示一条主线：**看卡 → 分析 → 方案 → 任务**。不现场安装、不逐项填表、不切换账号、不展开私有卡审批。

## 上台前准备

1. 启动两个服务，用林同学登录，浏览器停在算力广场资源卡区域。
2. 提前填写实验需求：模型训练、H100、1 张、约 20 GB、30 分钟、预算 20、公共大厅、综合均衡，截止时间留空。
3. 预先运行一次分析并生成方案，确认可行，先不要提交。回到算力广场，表单与结果保留在当前页面会话中。
4. 排练从大厅到提交页、再到任务页的点击路径。现场若容量变化导致提交失败，展示已有分析与方案即可，不花时间排错。

## 0:00–0:20｜介绍问题

**操作：**展示大厅。

大家好，我们的项目是 CampusGrove，校园 GPU 算力互助平台。我们希望解决一个矛盾：有的同学做实验排不到卡，但另一些实验室和个人 GPU，却有闲置时段。我们把这些资源连接起来，方便大家按需借用和共享。

## 0:20–0:45｜看懂资源

**操作：**点开个人 GPU 详情，指一下计划曲线，然后关闭。

每个 3D 小电脑代表一张 GPU，可以直接看到占用状态和资源归属。点开个人卡，还能查看卡主的项目计划和共享窗口，判断自己的实验适不适合借用。公共资源按范围开放，个人私有卡则保留卡主审批。

## 0:45–1:25｜分析与方案

**操作：**进入提交实验，展示提前准备的分析结果、策略卡片和预测。不要现场改填多组参数。

提交实验只需一张表单。系统根据目标、型号、显存、时长和预算，给出执行步骤、候选资源、预计费用和风险。这组单卡 H100 半小时的使用估价约为 2.4 积分。

预算不足或显存不兼容，会给出对应提示。我们还提供四种策略和条件排队预测，让用户知道为什么推荐、可能等多久，再核对方案后申请。

## 1:25–1:45｜展示状态变化

**操作：**核对后确认申请，进入“我的任务”指新建任务。不要额外讲续租、恢复或审批案例。

确认申请后，后端会更新资源和任务状态，用户可以追踪自己的实验，并在结束后释放资源。这次使用合成数据和模拟任务，预测不是预约，也没有真实执行 GPU 训练。

## 1:45–2:00｜收尾

**操作：**停留任务页，不再切新页面。

CampusGrove 希望把“到处问谁有空卡”，变成一个资源可见、方案可解释、共享有授权的校园算力互助流程。下一步，我们会完善真实节点接入和自动调度。谢谢大家。

## 超时或卡顿时

- 分析或提交等待较久：继续解释屏幕已有结果，不重复连点。
- 到 1 分 45 秒仍未提交：直接说“核对后即可发起申请，在任务页追踪状态”，随后念收尾。
- 不把任务创建成功、真实训练完成或准时获得 GPU 当作必须说出的结论，以界面实际状态为准。
- 多角色审批、资源贡献、收益、小组与画像留给问答，不在两分钟内逐页展示。
